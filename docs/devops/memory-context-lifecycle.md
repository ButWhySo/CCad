# CCad Agent context and memory lifecycle

## Sprint 976 canonical conversations, model projection, and TurnRecords

`ConversationStore` (`src/ccad_agent/conversation_store.py`) owns the durable, thread-keyed SQLite transcript. Each message is serialized with a stable ID and role; assistant tool calls, tool-call IDs, and tool names survive reload. Recognized secret-like key names and common token formats are redacted before persistence. The store records only allowlisted scalar tool findings, extracted explicit constraints and common PCB references/layers/nets, request/result summaries, outcome, tool IDs, and source message IDs in a versioned TurnRecord. This extraction is deterministic and bounded; it is not a model-generated account of every decision.

On thread activation, the runtime loads the saved model projection plus transcript messages newer than its projection boundary, isolates the in-process `session_messages` cache to that thread, then applies an estimated token/message budget at whole user-turn boundaries. Estimation uses serialized text and tool-call JSON length divided by four plus a per-message allowance, not the selected provider tokenizer. A very large completed latest turn can be compacted for active model history while the canonical transcript remains unchanged; if the current request itself cannot fit, the provider is not called. Completed turns persist once by stable message ID and create a TurnRecord. A provider-unavailable terminal response is recorded with that outcome. Pending approval/tool execution is stored as messages but is not summarized as completed until checkpoint resume reaches a terminal state.

The version-3 context envelope receives up to five same-thread TurnRecords selected by exact lexical token overlap plus the bounded thread recap. It includes source IDs in the provider-visible context and reports counts/source categories in safe context metadata. Retrieval is lexical, thread-local, and intentionally not described as semantic search. The recap contains at most six recent turns and is capped at 8 KiB. `/cc` stores a new bounded model projection; `/clear` sets an empty projection at the current canonical transcript sequence. Both leave canonical messages and TurnRecords untouched. Restart, per-thread isolation, tool-call identity, secret redaction, budget overflow, projection reset, recap, source-linked retrieval, and no-provider unavailable behavior are covered by `scripts/test_conversation_store.py`, `scripts/test_conversation_runtime.py`, and context-package contracts.

The GUI-map scenario `sprint976-conversation-20260924` used seven real mapped interactions. An isolated Python profile disabled provider initialization, then the harness independently read the database read-only and verified two canonical messages (one user, one assistant), one TurnRecord, and an empty projection after `/clear`. Four distinct PNGs were inspected; the CCad window—not the unrelated desktop foreground—was captured. Stdout contained the expected sequence-complete line and stderr was empty. Artifacts are local under ignored `artifacts/screenshots/` and are not committed.

Still open: migration of pre-existing checkpoint-only transcripts, conversation history UI and thread resume, cross-project historical retrieval, token counts from provider tokenizers, richer extraction of designs/rules/artifacts/proposals/transactions, embedding-based semantic retrieval and hybrid ranking.

## Provider request failure reporting

Provider adapter initialization reports configuration readiness, not proof that a model is reachable or supports every tool schema. When a provider call fails, CCad inspects nested HTTP status and structured SDK error fields without forwarding raw response bodies. It distinguishes payment-required, exhausted quota/credits, ordinary rate limiting, authentication, permission, model-not-found, timeout, and connection failures. If a provider supplies a valid numeric `Retry-After`, the user-facing failure includes a bounded delay; raw headers, bodies, credential text, and request payloads remain excluded. OpenAI-compatible and Anthropic adapters disable their SDK retry loops where the installed adapter supports that option, leaving CCad's bounded retry policy authoritative. The pinned Gemini LangChain adapter has a fixed internal retry decorator (two attempts) without a public configuration switch; this SDK behavior is documented and not misreported as a single attempt.

This note describes the request assembly and memory behavior implemented in Sprint 967 and the semantic conversation-history compaction added in Sprint 970. Whenever estimated request size crosses the configured large-context threshold, CCad sends the user a detailed end-to-end explanation of these stages plus safe counts and estimates. Diagnostics never expose prompts, design payloads, stored memory text, provider credentials, or raw tool arguments.

The chat command `/context [draft]` runs that same bounded accounting locally on demand. With a draft, it retrieves memory against that draft and counts it as a hypothetical user message; without one, it counts the current bounded conversation. It renders a complete breakdown in the chat stream even below the automatic threshold, and labels the result as a local preview for which no provider request was sent. It does not invoke the graph/model, run tools, add the command or draft to conversation history, or export draft/content text. The `provider_request_context` event and optional `CCAD_TRACE_DEBUG` stderr diagnostic carry safe count/identity metadata only; the visible explanation likewise contains counts and lifecycle metadata, not source content. `CCAD_AGENT_LARGE_CONTEXT_TOKENS` controls the automatic large-context threshold (default 4096 estimated input tokens; a minimum 512); the GUI harness lowers it only for its scoped validation process.

The visible preview is divided into request components, per-tier memory state, ranking/omissions, assembly lifecycle, project envelope, and privacy boundary. Each tier reports whether it is enabled, how many records are cached in this process, retrieved for this request, and durably stored. Development diagnostic JSON is forwarded to the Qt process log rather than rendered as a backend warning. On the Sprint 969 live UI-map run, the actual catalog contributed 59 tool schemas and the active project snapshot contributed 19,862 source characters; the total estimated input was 12,142 tokens. The child process remained provider-uninitialized for explicit runtime validation, and the GUI event reported `provider_request_sent:false`.

## Provider request assembly

Before a chat turn, the Qt Agent panel sends the user text, durable session ID, LangGraph thread ID, and current project context to the Python child process. Session binding also updates those identities before the first model request. The Python runtime selects the persisted provider/model and credential independently; credentials remain in the OS vault/process boundary and do not enter the context package.

The runtime configures enabled memory tiers for the current identities, retrieves up to eight matching records by query-term overlap, recency, and tier order, then constructs a versioned JSON envelope containing the project snapshot, selected memories, a conversation-message count, and mutation/secret policy. STM belongs to a task scope started explicitly with `/task start`, inspected with `/task status`, and ended with `/task end`; without an active scope, the current turn receives an isolated, non-retained STM identity. The chat command palette and `/commands`/`/help` expose these controls. Ending or replacing a task clears its process-only STM records. The conversation itself is sent separately as provider messages, not duplicated in this envelope. Tool schemas are bound separately to the selected model. Past tool-call payloads and multimodal blocks are counted where possible; unsupported multimodal payload sizes are reported as unestimated.

When the estimated request crosses its configured threshold, the explanation identifies the system prompt, project snapshot or summary, retrieved memory, conversation history, tool schemas, and any counted tool or multimodal payloads. It reports inclusion, truncation, omission, and source counts, as well as memory enabled/loaded/persistent/retrieved counts and ranking provenance. Its estimate is `ceil(text characters / 4) + 4 tokens per message + 8 tokens per tool`, not provider tokenizer output. The explanation appears before provider execution so quota errors do not hide it. It does not disclose the corresponding content. The exact request's safe identity includes package digest and context revision, and `provider_request_sent` distinguishes a local preview/no-op from a real call.

The budget report measures system instructions, project snapshot or summary, retrieved memories, envelope overhead, conversation messages, prior tool-call payloads, and bound tool schemas. Token counts use the explicit estimate `ceil(text characters / 4) + 4 tokens per message + 8 tokens per tool`; this is not a provider tokenizer. A selected-model context limit is shown only when current authoritative model metadata supplies it. At the configured large-context threshold, the Agent explains these sources, memory state, retrieval ranking, overflow omissions, truncation, and the model-limit uncertainty without including their contents. `CCAD_TRACE_DEBUG` writes the same safe counts and status to development stderr.

The project envelope has a character bound. If its full snapshot does not fit, the builder substitutes a valid counts-and-revision summary, then removes lower-ranked memories until the JSON is within budget. Exact included and omitted memory counts, source character counts, package digest, and context revision accompany the request. If even the safe summary does not fit, the request fails before provider execution instead of sending malformed or partial JSON.

## Memory tiers

All tiers use one local, atomic JSON store at `%APPDATA%/CCad/agent_memory.json` (or `CCAD_AGENT_MEMORY_PATH` when explicitly configured), but have distinct namespace and lifetime rules. Short-term memory uses a task UUID generated by the Python runtime; `/task start` holds that identity across turns for one durable Agent session, and `/task end` clears it. Starting a replacement task also clears the prior STM scope. Turns without an active task receive fresh, non-retained IDs; adding STM in that state is rejected rather than silently creating memory that cannot be retrieved later. STM is process-memory-only, isolated by task, and is discarded when disabled or when the process exits. At most 32 active session/task scopes and 64 records per task are retained; least-recently-used task scopes are cleared when the cap is reached. Conversation memory is durable and keyed by the LangGraph thread ID. Episodic memory is durable and keyed to the local OS user's CCad memory store, so it can be retrieved across that user's projects on this device. Project ID is not used to split episodic storage.

Enabling a tier loads its current namespace into a bounded runtime cache. Disabling it immediately empties that cache and prevents retrieval, add, and update through the manager; durable records remain untouched. Explicit list and delete operations remain available for managing stored records. A tier switch unloads the previous identity before loading the new one. Each toggle returns a snapshot of all tiers, so Personalisation shows enabled state plus runtime and persistent record counts together; `Manage memories` uses the same typed IPC and tier manager as `/memory` commands.

Scope labels are retained as record metadata and can be used for explicit list/delete filters. Retrieval isolation is enforced by tier and namespace; scope labels are not semantic retrieval filters. Defaults are `task` for short-term, `conversation` for LTM, and `user` for episodic records. Memory capture is explicit through `Manage memories` or `/memory add`; ordinary conversation is not automatically learned or persisted.

Writes reject secret-like content or metadata, including common API-token prefixes and bearer values. Legacy secret-bearing records are excluded from runtime retrieval and the Manage Memories listing; reset remains available to remove them. Expiry values must be timezone-aware ISO-8601 timestamps and expired records are removed on load or retrieval. Normalized exact duplicates resolve to the existing entry. Adds and updates reject high lexical-overlap near-duplicates within the same tier and namespace, identifying the existing record so users can update it deliberately. The detector requires at least five distinct terms and Jaccard overlap of at least 0.88; this is lexical similarity detection, not a claim of semantic equivalence. Durable namespaces retain the newest 64 records; STM caches retain 64 per task, across at most 32 tasks. This bounded retention is separate from explicit semantic compaction, which is implemented below.

`/memory list`, `add`, `update`, `delete`, and `clear` route through `MemoryManager`; they no longer write directly to `MemoryStore`. A clear by scope only affects matching namespaces, while clear all/reset removes durable records across namespaces. The Settings reset action and individual record deletion require an explicit confirmation. Disabling a tier is not deletion and does not clear chat transcripts or LangGraph checkpoints.

Enabling LTM or episodic memory first opens the durable JSON file, validates its records, creates an empty store if it does not exist, and loads the selected tier namespace before setting the runtime enabled flag. Corrupt JSON is not treated as an empty store and is never overwritten by activation or a later add. An unavailable or corrupt store reports a safe category, unloads the affected process cache, disables retrieval, and renders the persistent count as unknown (`?`). Memory preference changes use a verified atomic configuration write before activation; failed activation attempts to restore the prior saved preference. `memory_state` returns both persistence and runtime state so Settings can display what actually happened.

Sprint 971 validates those guarantees through a real offline orchestrator subprocess using a disposable user profile, memory file, checkpoint DB, and project sentinel. It toggles LTM and episodic tiers, verifies LTM records and checkpoint data survive disablement, refuses reset without confirmation, performs confirmed reset only on the test namespace, and preserves malformed memory-file bytes. The app-owned GUI-map scenario exercises settings toggles, manage-memory input, title/scope/content save, and the reset confirmation's cancel button without touching the user's profile. It closes and reopens Settings, navigates back to Personalisation, and checks visible toggles against their original state and persisted configuration; the earlier mismatch was a test targeting error because those controls are hidden on the default General page. The Release build and full CTest passed 104/104, targeted Pyright returned zero diagnostics, and all 42 generated screenshots plus stdout/stderr were inspected. Durable memory semantic compaction remains unimplemented and separate from chat-history `/cc` compaction.

The `/cc` and `/compact` commands apply only to conversation history. They serialize bounded older turns while retaining the latest four original messages, omit unsafe or non-text content and tool arguments, and ask the selected model for a concise recap with tools disabled. The recap is bounded, checked for secrets/instruction-like content, and rejected unless it is shorter than its source. A successful recap replaces older messages in the actual LangGraph checkpoint and is read back for verification; a failed update attempts restoration and reports recovery failure distinctly. Pending graph work is not compacted. The user is told before the provider request that bounded conversation text will be sent and may consume quota; reports distinguish prepared, sent, complete, and failed states. This operation does not compact durable memory records.

Sprint 974 adds a separate `/memory compact plan tier:ltm|episodic scope:<scope>` lifecycle. Planning selects bounded source records locally and reports safe counts plus selected provider/model and an estimated request size; it neither sends nor writes source text. The user must separately issue `/memory compact send:<id>`, which sends only the selected durable records to the raw chosen model with tools disabled. A validated summary stays in process memory and is shown for review; only `/memory compact apply:<id>` atomically replaces unchanged source entries. Cancellation, expiry, memory disablement, and thread/namespace changes discard the process-held plan. Stale records are checked before sending and again before application, and failures preserve the original store. No provider request is made by plan/cancel. The live provider-backed summary/apply path remains unverified until an explicitly authorized quota-bearing run.

## Sprint 977 context broker and targeted retrieval

`context_broker.py` turns the current request, task identity, project identity/revision, active editor, selected object identifiers, workflow, recent TurnRecords, and a bounded recent-message slice into deterministic retrieval signals. Sensitive token-like strings are removed before signal digests and lexical queries are produced. `ContextBroker.prepare()` first asks `MemoryManager` to reconcile runtime tier state, then retrieves only enabled task-, thread-, current-project-, and local-user-scoped records. Current-project LTM has its own opaque SHA-256-derived namespace; the manifest reports its availability and safe persistent count. Matching uses deterministic BM25, removes near-duplicate entries against recent conversation/TurnRecords, and caps records and serialized character volume according to `CCAD_AGENT_MEMORY_TOKENS` (default 1000 estimated tokens, clamped to 64–8000) and eight entries. The cache identity includes project ID/revision, signal/query digests, history count, tier identities/enabled state, loaded record identity/update/content hashes, and budget. Memory writes, tier changes, task changes, thread switches, and project switches invalidate or change the held context identity; cached entries cannot survive a tier being disabled.

The versioned TurnContext is assembled before the first reasoning/model call and its selected memory records are added to the provider envelope. The envelope includes a short summary made from safe memory titles and a content-free manifest with tier availability, approximate counts, scope names, historical-turn count, and explicit semantic/project-index readiness flags. These are separate from canonical storage and from the package's exact source-backed memory entries. When envelope limits are reached, repeated summary text is dropped, then manifest fields are compacted before relevant memory entries are removed; package serialization remains valid and metadata reports omissions. The summary is not a semantic condensation of record bodies, and current lexical ranking does not prioritize explicit preferences over other matching facts.

During a live turn, `ccad_search_memory` is bound beside the native broker catalog as a read-only LangChain tool. It searches the enabled current-thread namespace and the active native project's LTM namespace, plus the enabled local-user episodic namespace, merges/deduplicates records with the current set, reapplies the budget, increments the context version, and returns source IDs, tier/scope, rank provenance, and a safe manifest. Project LTM records use a stable SHA-256-derived opaque namespace from the native project ID, so they persist across conversations within that project without sharing the thread or user-global namespace. Missing project identity makes project writes unavailable and project records are not loaded; switching project reloads the LTM runtime, changes the context cache identity, rejects refresh against a stale turn context, and invalidates project-bound compaction plans. Existing `scope:project` values on non-LTM tiers are rejected and excluded from retrieval. Explicit full reset still deletes durable records across namespaces; ordinary project changes and scope operations do not. The manifest reports project-scope availability and the count of safe durable project records, never record contents. Langfuse receives a nested `context.assemble` observation with child `memory.retrieve` and `context.package` spans and content-free counts/digests. This assembly currently occurs before the later `agent.turn` trace is started, so the full same-root context-to-model hierarchy is still open.

Offline evidence is provided by `scripts/test_context_broker.py` (signal/secret redaction, relevance, cache/thread isolation, write/disable invalidation, targeted refresh, and truthful missing-index manifest), `scripts/test_agent_memory_search_tool.py` (actual bound tool, isolated store, result relevance and version growth), `scripts/test_context_budget.py`, the JSON-RPC context contract, and the native catalog protocol contract. Qt MinGW Release build and full CTest pass (110/110), changed Python modules pass Pyright, and clangd reports no diagnostics for the changed GUI translation unit. The seven-action isolated GUI-map scenario visibly attaches one memory record, demonstrates the provider-independent response, then verifies chat-clear projection behavior while preserving the canonical transcript; all four distinct screenshots, stdout, and stderr were inspected. No provider request was sent. The CMake language-server handshake timed out, but actual CMake configure/build and CTest succeeded. Secret scans, commit, merge, and publication are tracked in the Sprint 977 delivery status.

## Verification boundary and remaining limitations

Offline tests exercise store CRUD, namespace isolation, runtime unloading, tier gating, persistent metadata preservation, expiry, secret rejection, duplicate handling, retention, reset, and slash-command operations. The Sprint 967 Release/CTest gate passed 98/98; its Settings/Manage Memories GUI-map pass performed ten mapped actions per pass, with all 26 screenshots and captured stdout/stderr inspected. Sprint 969 added and verified the provider-free large-context chat preview: Release build succeeded, full CTest passed 100/100, targeted Pyright reports zero diagnostics, and the app-owned GUI-map flow completed eight mapped interactions with all nine screenshots and logs inspected. No provider request was sent for this proof. clangd's source check timed out without diagnostics and remains an explicit validation limitation.

STM task IDs persist only while a `/task` scope remains active for that session; unstaged turns each receive a fresh task ID. The bounded in-process STM cache does not survive application restart. Episodic storage is local-user scoped, not synchronized across devices. Memory is not automatically captured from ordinary chat. Durable semantic compaction is an explicit user-driven operation; its provider-backed summary/apply success still requires opt-in live verification. These are deliberate visible limitations, not claims of completed behavior.

## Sprint 989 bounded BM25 retrieval

`lexical_retrieval.py` applies standard deterministic BM25 scoring to bounded candidate documents with matched-term provenance. `MemoryManager` uses it across enabled STM, thread/project LTM, and local-user episodic records after expiry pruning and runtime scope loading; `ContextBroker` continues to enforce the existing memory entry and estimated-token budget. Conversation TurnRecords use the same scorer. Historical search first selects at most 500 compact recaps from threads whose persisted native project ID exactly equals the active project, ranks those summaries, expands at most 16 recaps into their source turns, and injects no more than eight current-thread plus same-project turns. Multi-term history queries require at least two matched terms; no-match and one-term-only weak history candidates are omitted. No raw transcript is opened for retrieval.

Provider context preserves each retrieved turn's thread ID, turn ID, and source message IDs, while memory provenance carries BM25 score, matched terms, rank, tier, and opaque namespace digest. Candidate content remains local to retrieval; trace attributes remain counts/digests. Embeddings, cross-project history, RRF, MMR, preference/correction weighting, and provider-specific tokenizer budgets remain unimplemented and are not represented as ready. Offline contracts: `scripts/test_lexical_retrieval.py`, `scripts/test_memory_manager.py`, `scripts/test_conversation_store.py`, `scripts/test_context_budget.py`, and existing context-broker tests.
